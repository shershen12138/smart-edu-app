# Ubuntu 24.04 校园版更新

适用对象：已经使用 `Ubuntu24部署包_20260930` 部署在 `/opt/coursejudge` 的电脑。沿用这套 Linux 部署的 MySQL、Redis、批阅容器、校园网防火墙、开机启动及动态 IP 脚本。

**这是已有环境的更新器，不是新电脑安装器。** 同学第一次在自己的电脑上测试，请看 [新电脑安装与测试](../../docs/GETTING_STARTED.md)。源码不含 Docker 安装程序、原始离线镜像或老师私有题目包。

Gitee 的 `codex/simplified-coursework` 分支已包含本目录全部文件。单独发送的 `Ubuntu24更新包_20261006_*.zip` 也是该分支某次提交的源码快照，两者选一份使用即可；想要后续最新修改，以 Gitee 最新提交为准。安装教程等文档后续更新后，不会自动改变已经下载的旧 ZIP。

## 在哪里运行

以下操作全部在**实验室 Ubuntu 部署电脑的终端**执行。

1. 从 Gitee 下载 `codex/simplified-coursework` 分支的最新源码 ZIP，解压。
2. 打开解压后的源码文件夹：里面应该同时看到 `manage.py`、`school` 和 `deploy`。
3. 在该文件夹空白处右键，选择“在终端打开”。先确认位置：

   ```bash
   ls manage.py deploy/linux/update.sh
   ```

4. 找到这两个文件后运行：

   ```bash
   sudo bash deploy/linux/update.sh
   ```

   输入 Ubuntu 登录密码。输入密码时终端不显示字符属于正常现象。

5. 等终端显示“升级完成”和“网站已启动：http://当前IP:8000”，再用该地址访问。

如果已经克隆过仓库，先在源码目录运行 `git pull --ff-only`，再执行第 4 步。源码 ZIP 无需安装 Git。下载来的目录与 `/opt/coursejudge` 是两个目录，请不要用源码覆盖原部署目录。

更新前可在该终端执行 `sudo test -f /opt/coursejudge/.env && echo 原配置存在` 以及 `sudo docker version --format '{{.Server.Os}}'`，应看到配置存在和 `linux`。若缺少原目录或镜像，先核对是不是操作错电脑；不要用账号初始化或空数据库替代原环境。确认 `/opt/coursejudge` 所在磁盘有空间保存本次数据库和全部上传文件的备份。

## 脚本会做什么

- 使用现场已有的 Linux 网站和批阅镜像构建更新，不重新下载 Python 依赖。
- 构建成功后暂停网站及批阅，备份数据库、私有文件、原 `.env`、Compose 配置和版本记录。备份位于 `/opt/coursejudge/backups/update-日期时间-版本/`。
- 保留原账号、密码、网络设置、数据库和数据卷名称；不创建演示账号，不重新导入章节。
- 执行 `0009_data_lifecycle_and_teacher_outputs` 数据库迁移。
- 永久清理旧版已经标记删除的班级、作业、账号及其关联数据；清理私有存储中不再被任何记录引用的文件。**已归档但未删除的数据保留。**
- 更新并启动网站、批阅和调度服务。源码同步到原部署包的 `app` 目录，刷新文件校验清单。

删除与归档是两种不同操作。永久删除会移除数据库记录及专用文件；其他作业仍在使用的批阅包不会删除。保留必要的操作日志。文件删除暂时失败时会自动重试。

升级失败时，终端会显示错误及备份目录，服务保持暂停以避免继续写入。保留完整输出排查，不要执行初始化、重置账号、删除数据卷等操作。已经执行数据库迁移的情况不能只切换旧镜像作为完整回滚；需要结合备份恢复数据库和文件。

## 更新后逐项检查

1. 管理员进入教学班列表，查看“在班人数”；进入该班名单，核对人数与成绩报表一致。人数只计当前有效在班的学生身份账号，停用登录但未移出班级者仍计入。跨班同一账号在各班各计一次，单班不重复计数。
2. 名单显示总人数、每页条数、连续序号、页码及跳转框。全平台账号总数与某班人数是不同口径，不应混用。
3. 导入名单先预览，再点击“确认导入”。完成后显示新增/已有账号数量；单班名单跳转到该班筛选结果，多班名单跳转到名单总页。
4. 管理员班级名单页不再显示“本班作业”或学生成绩入口。管理员不能进入教师作业管理接口。
5. 教师授权选项显示“班级编号 · 班级名称 · 学期”。
6. 教师打开批阅详情，可查看期望结果和实际结果。学生页面不输出这些信息。升级前未保存的实际结果不能凭空补回，显示“未记录返回结果”；期望结果以该次提交的快照为准。评分规则保持现有用例比例计分逻辑。
7. 两种批阅作业的班级结果页均提供“打包下载作业（每人最后一次）”，需要该班导出权限；机器批阅下载源码 `.py`，人工答案 ZIP 会展开到“学号_姓名_提交次数”目录。未提交、文件缺失或答案 ZIP 损坏会在打包结果中明确列出。
8. 两种 ZIP 作业都支持在“修改作业”页更新包内单个文件。机器批阅只有 Word 说明文档更新不重评，`sample*.py` 及其他批阅文件变更须经 Docker 验证后重评已有提交；非机器批阅材料更新不调用 Docker，也不改动已有人工成绩。验证失败时旧版本和旧成绩保持不变。
8. 管理员进入“归档管理”，勾选某班“归档”并保存。各角色的正常列表、旧详情和下载链接均不可访问该班内容；仅管理员归档页显示恢复所需的班级编号、名称和学期。取消勾选并保存后恢复原数据和原授权。
9. 若某个学生还有其他未归档教学班，该学生账号仍可在对应的日常名单中看到；归档班的名单关系不会被修改其他班的操作清除。

日常状态检查仍使用原命令：

```bash
sudo bash /opt/coursejudge/scripts/status.sh
```

## 单独检查旧数据清理（维护人员）

更新脚本已自动处理，不需要重复执行。需要手动核查时，默认命令只预览：

```bash
cd /opt/coursejudge
sudo docker compose --env-file .env -f compose.yaml run --rm --no-deps web python manage.py purge_deleted_data
```

`--apply` 才真正清理。仅在 Web、worker、beat 全部停止并完成备份后，才可加 `--offline` 清理不满 24 小时的无引用文件，避免与新上传同时发生。
