# 软件产品原型测试与评估报告

> 对象：smart-edu-app（弱项练习与智能批阅系统）
> 内容：原型测试方法、实际效果与用户期望、可用性、竞品比较、功能设计、用户体验

---

## 1. 软件产品原型测试方法

原型阶段的核心思路是**低成本验证、快速迭代**，不必等全部功能开发完成：

| 方法 | 做法 | 在本项目中的对应 |
|---|---|---|
| 纸面原型 / 草图走查 | 画出关键页面流程，让用户口述操作路径 | 学生端"练习 → 提交 → 结果"三页流程草图 |
| 可点击原型（Axure / Figma） | 高保真交互原型，观察用户是否卡壳 | 提交代码后的加载态与批阅结果雷达图交互 |
| 任务观察法（用户测试） | 给 5~8 名真实学生下达任务："生成训练计划并完成一题"，记录完成率、耗时、出错点 | 观察学生能否独立找到训练计划生成入口 |
| 出声思维法 | 用户边操作边说出想法，暴露认知偏差 | "样例用例可见、隐藏用例只给结论"是否被正确理解 |
| A/B 对照 | 两种文案 / 布局各测一组用户 | 入口命名："弱项练习" vs "智能训练" |
| 问卷 + SUS 量表 | 用系统可用性量表量化打分（见第 3 节） | 每轮迭代后发放 |

**要点**：原型测试验证的是"用户能不能用、想不想用"，不是代码正确性——后者已由 685 个自动化测试覆盖，两者互补。

## 2. 实际效果与用户期望

### 学生期望："告诉我哪里弱、给我练什么、练完有反馈"

实际效果：

- 弱项画像依据作业评测报告逐题缺陷归入知识点 Tag 库；
- 按任务独立生成训练计划，弱项知识点自动匹配训练题；
- 提交后秒级返回批阅结果与逐用例明细。

**结论：期望基本满足。**

### 教师期望："不用手工批阅、能看到全班弱项分布"

实际效果：

- 机器批阅在受限 Docker 容器中运行，按用例通过比例自动计分；
- 教师端提供班级知识点弱项分布汇总。

**结论：满足，但存在期望落差** —— 教师还期望"一键导出讲评材料"，目前缺失，列入下一迭代。

### 落差管理

非机器批阅的题目（主观题）仍需教师评分。产品宣传时应明确"自动批阅的覆盖范围"，避免用户期望过高。

## 3. 产品的可用性

按 Nielsen 十大可用性原则抽查：

| 原则 | 现状 | 评价 |
|---|---|---|
| 系统状态可见 | 提交后即时提示"通过 x/y 组用例"；批阅服务不可用有明确报错 | ✅ |
| 防错 | 空代码提交被表单校验拦截；训练题失效不给 404，引导回训练页 | ✅ 设计良好 |
| 一致性 | 管理员 / 教师 / 学生三角色统一布局，返回按钮位置统一 | ✅ |
| 容错 | 批阅基础设施故障时保留提交记录，可稍后重试，不丢学生代码 | ✅ |
| 效率 | 题目编辑器预填模板代码，可反复练习，一次点击重新提交 | ✅ |
| 美观简约 | 批阅结果雷达图信息密度偏高 | ⚠️ 可增加悬浮说明 |

**SUS 量化建议**：发放 10 题 SUS 问卷，目标 ≥ 68 分（行业平均水平）。当前主观估计在 70~75 区间："防错"与"即时反馈"是加分项，"信息密度"是主要扣分项。

## 4. 竞品比较

| 维度 | 本项目 | 头歌 EduCoder | PTA 拼题A | 力扣 / 洛谷 |
|---|---|---|---|---|
| 定位 | 课堂教学 + 弱项诊断闭环 | 实训教学 | 高校考试 / 作业 | 社区刷题 |
| 机器批阅 | ✅ 容器沙箱按用例计分 | ✅ 步骤关卡 | ✅ | ✅ |
| 弱项画像 → 自动出题闭环 | ✅ 核心差异点 | ❌ | ⚠️ 仅部分统计 | ❌ 仅个人统计 |
| 知识点 Tag 库 + 评分标准自动生成 | ✅ | ❌ | ❌ | ❌ |
| 私有化部署 | ✅ Docker 化校园部署 | 商业 SaaS | 商业 SaaS | ❌ |
| 题库规模 | ❌ 依赖教师建题 | ✅ 海量实训课程 | ✅ 高校共建 | ✅ 海量 |

**结论**：差异点在"诊断 → 训练"闭环与私有化部署能力；短板在题库生态。短期依靠分层题库文档与题库导入弥补，长期建议支持导入主流格式（PTA / Markdown 题目包）。

## 5. 功能设计

按"用户价值 × 实现成本"评估现有功能：

### 高价值、高完成度

- **机器批阅**：受限容器沙箱执行、按用例通过比例计分，杜绝学生数据外泄；
- **弱项画像**：依据首次提交的评测报告逐题归因，避免后期刷题污染画像；
- **训练计划**：LLM 生成 + 规则兜底双通道，LLM 不可用时仍能从题库出题，不伪造结果。

### 设计亮点

- 归档与永久删除是两种操作，归档内容无法通过旧 URL 绕过——权限收口干净；
- 样例用例可见、隐藏用例只展示结论——兼顾教学引导与防抄袭；
- 教师可查看期望输出与实际输出，学生侧答案始终隐藏——信息不对称设计合理。

### 待改进

- 缺少错题本 / 单题重练入口（目前只能经训练计划进入）；
- 缺少题目讨论区；
- 教师端无讲评材料导出。

## 6. 用户体验

### 流畅点

提交 → 批阅 → 逐用例结果页一气呵成，本地批阅等待在秒级。

### 摩擦点与改进路线

| 问题 | 改进方案 | 成本 / 收益 |
|---|---|---|
| 批阅失败提示"需要 Docker"，对学生是黑话 | 翻译为"服务器暂时繁忙，请稍后重试" | 成本最低、收益最大，优先做 |
| 训练计划重新生成后旧题链接失效，学生困惑"题去哪了" | 旧题保留只读入口 | 中 |
| 雷达图六大维度缺少与具体错题的联动 | 报告维度支持点击跳转对应错题 | 中 |
