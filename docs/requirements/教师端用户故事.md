# 课码 · 教师端用户故事（INVEST）
---

## 用户故事一：作业布置与机器批改结果复核

### 故事描述

| 要素              | 内容                                                                     |
| --------------- | ---------------------------------------------------------------------- |
| **角色（Role）**    | 作为一名讲授 Python 课程的教师                                                     |
| **功能（Feature）** | 我想要在系统中创建编程作业（题面、测试数据、截止时间）并发布给班级，在机器自动批改完成后复核结果、调整评分、写评语并在代码行上留批注        |
| **价值（Value）**   | 以便把重复性的"跑代码、对结果"交给机器、学生提交后立刻得到反馈，而我只需复核和指导，保证最终成绩"机器判对错 + 教师判好坏"两者结合     |

**故事陈述**：作为一名讲授 Python 课程的教师，我想要布置带测试数据的编程作业并复核机器批改结果、进行人工评分与批注，以便学生即时获得准确反馈、我聚焦高质量的讲评与指导。

### 验收标准（Acceptance Criteria — Gherkin 语法）

```gherkin
场景：成功创建并发布一份作业
  Given 教师已登录教师账号并进入"作业管理"页面
  When 教师填写作业标题与题面（Markdown）、上传测试数据文件、设置截止时间"2026-10-31 23:59"
  And 教师选择发布班级"1班"并点击"立即发布"
  Then 系统应在 3 秒内保存，作业状态变为"已发布"
  And 该班级学生端应在 60 秒内看到该作业，并可进行上传提交

场景：查看班级提交进度并催交
  Given 班级共 40 人，其中 35 人已提交、5 人未提交且未到截止时间
  When 教师打开该作业的详情页
  Then 页面应在 10 秒内显示"已提交 35（87.5%）/ 迟交 0 / 未提交 5"
  And 教师点击"催交"后，5 名学生应各收到 1 条含作业名与截止时间的提醒通知
  And 同一学生在 24 小时内不应收到超过 1 次催交

场景：复核机器批改并调整评分
  Given 学生某次提交的机器批改得分为 80（满分 100），状态为"机器批改完成，等待教师复核"
  When 教师填写调整分 -10、选择理由"命名不规范"并保存
  Then 最终成绩应更新为 70，并记录评分人与评分时间
  And 学生端应在 10 秒内看到"机器批改 80，教师调整 -10（命名不规范）"及合并成绩
  And 系统应向学生推送一条"作业已批改"的消息通知

场景：调整分数缺少理由
  Given 教师正在复核一份提交
  When 教师填写调整分 -10 但未选择或填写任何调整理由
  Then 系统应阻止保存并提示"请选择或填写调整理由"

场景：在指定代码行添加批注
  Given 教师正在查看学生的 Python 代码，第 12 行存在"if A == A[::-1]"缺少冒号的错误
  When 教师选中第 12 行并添加批注"此处缺少冒号，注意 if 语法"
  Then 批注应显示在该代码行右侧
  And 学生打开自己的提交时，应在同一位置看到相同批注

场景：机器批改服务不可用
  Given 教师打开一份刚提交的作业
  When 自动批改服务超时或不可用
  Then 页面应显示"评测服务暂不可用，已加入重试队列"
  And 该提交不应显示为 0 分，也不计入学生成绩
```

## 用户故事二：班级知识点学情分析与 AI 讲评助手

### 故事描述

| 要素              | 内容                                                                       |
| --------------- | ------------------------------------------------------------------------ |
| **角色（Role）**    | 作为一名讲授 Python 课程的教师                                                       |
| **功能（Feature）** | 我想要在仪表盘上看到基于全班历次作业分析出的知识点掌握情况与高频错误分布，并让 AI Agent 汇总典型错误、生成讲评材料和针对性练习题       |
| **价值（Value）**   | 以便下一节课能精准讲评"全班真正不会的知识点"，而不是凭印象猜，同时用几分钟生成讲评材料替代过去一晚上的手工整理                   |

**故事陈述**：作为一名讲授 Python 课程的教师，我想要查看班级维度的知识点掌握度与错误分布，并让 AI Agent 生成讲评清单与强化练习，以便用数据驱动教学决策、提高讲评效率。

### 验收标准（Acceptance Criteria — Gherkin 语法）

```gherkin
场景：查看班级知识点掌握度仪表盘
  Given 班级已有至少 5 份已被批改的作业提交
  When 教师进入"班级学情"页面
  Then 系统应在 5 秒内渲染知识点仪表盘，展示各知识点的通过率、平均分与提交数
  And 通过率低于 60% 的知识点应以醒目颜色（如红色）标记为"薄弱"
  And 知识点按通过率升序排列，最薄弱的排在最前

场景：下钻查看高频错误明细
  Given 仪表盘显示"列表切片"知识点有 14 份未通过的提交
  When 教师点击该知识点的"未通过 14 人"
  Then 系统应展开学生名单（学号、姓名、错误类型、提交链接）
  And 每条记录可跳转到对应提交的代码与出错用例详情

场景：AI Agent 生成讲评材料
  Given "列表切片"已被标记为班级薄弱知识点
  When 教师点击"生成讲评材料"
  Then 系统应在 15 秒内生成讲评清单：知识点说明、全班通过率、3 份典型错误代码示例（学生姓名脱敏）
  And 教师可一键将清单保存为 PDF 或复制为 Markdown

场景：基于薄弱知识点布置强化作业
  Given 教师已查看"列表切片"的学情分析
  When 教师点击"生成强化练习作业"
  Then AI Agent 应在 30 秒内生成一份草稿作业，含 5 道针对该知识点的练习题与测试数据
  And 教师可修改后按正常流程发布，学生端表现为一次普通作业并可进入各自的强化练习

场景：数据不足时的降级展示
  Given 班级已被批改的作业提交少于 5 份
  When 教师进入"班级学情"页面
  Then 系统应提示"提交数据不足，暂无法生成可靠的学情分析"
  And 页面不渲染空白图表，并提供"查看已批改作业列表"的跳转入口
```
