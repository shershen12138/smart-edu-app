# Python 教学辅助系统 · Tag 库 v1.0

> 用途：为「考点分析 Agent」与「薄弱点练习生成 Agent」提供同一套共享词表，使"题目 → 考点标签"与"薄弱点标签 → 练习题"两个环节可以互相对齐、互相关联。
> 结构：一级 = 单元（Unit）｜二级 = 模块（Module）｜三级 = 具体标签（Tag）
> 来源：基于《Python 学习知识库》全量资料（1014 条）的术语提炼，覆盖零基础入门 → 语法 → 容器 → 函数 → 模块 → 文件异常 → 面向对象 → 高阶特性 → 数据处理 → 爬虫 → 算法题 → 工程实战全链路。

---

## 0. 设计说明（给接入方看）

**三层结构的职责**

| 层级 | 含义 | 粒度 | 典型使用方 |
| --- | --- | --- | --- |
| 单元 Unit | 学习阶段 / 教学章节，一个学期的天然切分 | 粗 | 课程进度、能力雷达的大维度 |
| 模块 Module | 一个可独立讲授的知识块，通常对应 1～2 课时 | 中 | 薄弱点归并、组卷范围、错题归类 |
| 标签 Tag | 一个可被单独考查的**具体名词**，最小可诊断单元 | 细 | 题目考点打标、练习题检索、错因定位 |

**四条硬规则**

1. **一词一义**：标签名全局唯一，不做同义词重复。同义写法只保留一个（用「列表推导式」，不另设「推导式」）。
2. **可考性**：每个标签必须能单独出题或有明确的正确/错误判定。不可考的（如"编程思想"）不入库。
3. **名词化**：一律用名词或名词性短语，不写句子、不写动作描述。
4. **稳定优先**：标签只增不改。确需更名时保留旧名做别名，不直接删除，避免历史题目打标失效。

**ID 规则**：`单元号-模块号`（如 `U05-M02`），标签唯一键 = 标签名本身。新增标签必须挂在已有模块下；确实无法归入时新建模块并申请新的段号。

# 附录 C：两个 Agent 的接口约定

## C-1 考点分析 Agent 的输出

对每道题输出结构化考点，`role` 区分主考点（决定能否做对）与次考点（影响解法优劣）：

```json
{
  "question_id": "Q1024",
  "tags": [
    { "tag": "列表推导式", "module": "U05-M06", "unit": "U05", "role": "primary", "weight": 0.45 },
    { "tag": "条件筛选推导式", "module": "U05-M06", "unit": "U05", "role": "primary", "weight": 0.35 },
    { "tag": "浮点误差", "module": "U02-M02", "unit": "U02", "role": "secondary", "weight": 0.20 }
  ],
  "ability": ["代码编写", "边界处理"],
  "error_modes": ["循环边界 off-by-one"]
}
```

约束：

- 每道题 1～3 个 primary，0～3 个 secondary，tag 必须命中本库词表，未命中时置 "tag": null 并记录原始短语到 unmatched，供人工补词表。
- weight 在同一题内归一化到 1，用于练习生成的难度配比。

## C-2 薄弱点练习 Agent 的取题规则

1. **按标签召回**：以学生错题聚合出的 `primary` 标签为查询键，召回同标签题目。
2. **加权聚合**：标签权重 = Σ(错题次数 × 该题该标签 weight)，取 Top-N 作为本轮练习目标。
3. **层级上溯**：某标签题量不足（< 3 题）时上溯到其 `module` 取同模块其他标签；仍不足再上溯 `unit`。
4. **前置补链**：若目标标签的模块在课程顺序上晚于学生当前进度，则跳过，改出前置模块的巩固题。
5. **错误模式定向**：优先选"能触发该学生历史错误模式"的题（如历史常犯 `索引越界`，则选边界用例多的题）。
6. **难度阶梯**：单轮练习按 记忆 → 阅读 → 编写 三档递进，每档 2～3 题。

## C-3 词表维护

- 新增标签：由教研在月度评审中确认，写入对应模块末尾，不打断现有顺序。
- 停用标签：标记 deprecated，保留映射关系，历史数据不重算。
- 同义合并：只保留使用频率高的名称，另一名作为 alias 参与匹配。
- 规模控制：单模块标签建议 ≤ 25 个，超出说明模块粒度过粗，应拆分模块。
